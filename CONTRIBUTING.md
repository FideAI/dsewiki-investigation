# Reviewing the investigation

We welcome corrections, alternative readings and reproduction reports. A useful challenge identifies:

1. The assessment ID (for example, `C263-09`), transition ID or publication finding.
2. The exact source passage or incident record.
3. What our assessment misses, with the strongest alternative interpretation.
4. The proposed correction and any dependent findings it changes.

Please distinguish a factual contradiction, insufficient support and a reasonable inference. An omitted topic is not a correct answer; a report can contain useful and problematic analysis at the same time. Read the codebooks before changing labels.

Use an issue for discussion, or a pull request for a proposed change. Changes to review JSON may require corresponding pair mappings. Run source validation, rebuild the study, rerun analysis, update the reconciliation notes and render deliverables. Regenerate the explorer and release manifest only after reviewing the changes. Keep earlier corrections visible. Do not include private review exports, secrets or full third-party source dumps.

The local app stores review decisions separately. An approval is agreement with a specific assessment or wording; it neither changes the study automatically nor validates every judgment behind a publication statistic. Describe any independent review with its actual scope and reviewer consent, rather than treating issue counts as peer review.
